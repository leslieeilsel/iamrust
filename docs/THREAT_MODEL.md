# 威胁模型

## 资产与边界

核心资产包括账号密码、访问/刷新令牌、消息与附件、好友/群关系、本地缓存密钥、管理令牌和发布签名密钥。主要信任边界位于原生 GPUI 界面与客户端服务层、客户端与 REST/WebSocket API、PostgreSQL、对象存储、SMTP/可选外部服务，以及 CI 发布环境之间。

原生 UI 不直接执行任意 SQL、Shell 或文件系统命令。访问令牌仅驻留内存，刷新令牌和可选本地缓存加密密钥进入操作系统凭据库。

## 主要威胁与控制

- 账号接管：Argon2id、短期访问令牌、轮换刷新令牌、复用检测、登录限流、设备列表和远程撤销
- 枚举与越权：统一认证错误、不可预测 UUID、每次资源访问执行成员/所有者校验
- 内容注入：消息按普通文本渲染，通知文案清理控制字符，外链只允许明确协议；不解释消息中的 HTML 或脚本
- 本地泄露：可选 AES-256-GCM 缓存加密、凭据库密钥、日志敏感字段清除、设置中的本地数据清理
- 恶意媒体：服务端限制文件名、路径、大小、数量、MIME、文件头和哈希；下载内容默认不执行
- 重放与乱序：`client_message_id` 幂等、服务端序列号、事件 ID 去重和单调同步游标
- 通知泄露：通知总开关、会话免打扰、预览开关、隐私模式、前台和自身消息抑制
- 桌面劫持：单实例标识按用户隔离；第二实例只创建固定激活标记，不接受任意路径或命令
- 供应链：Cargo/pnpm 锁文件、cargo-deny、依赖审查、SBOM 与发布校验和
- 管理面滥用：独立高熵令牌、常量时间摘要比较、管理动作审计；生产限制 `/admin` 与 `/metrics` 的网络来源

## 当前限制

- 传输可以由 TLS 保护，但当前没有端到端加密；服务端能够处理消息内容。
- 本地缓存加密是用户可选项，不等同于设备全盘加密；解锁系统账户的攻击者仍可能访问应用运行态。
- 当前候选安装包默认未签名，不能把校验和替代为平台代码签名或公证。
- 正式稳定版前仍需要三平台安全冒烟、第三方依赖复核和外部安全测试。

认证、本地加密、媒体处理、通知、桌面集成、更新或跨端同步发生重大变化时，应重新评审本文件。在完成独立密码学设计、多设备密钥验证、恢复机制和外部审计前，不得宣称支持 E2EE。
